# HWP → PDF 변환기

한글(HWP/HWPX) 파일을 웹 브라우저에서 업로드하면 자동으로 PDF로 변환해주는 간단한 Flask 웹 애플리케이션입니다. 변환은 LibreOffice의 헤드리스(headless) 모드를 이용합니다.

같은 앱에 **협력사 종합 모니터링 대시보드**(`/partners`)가 포함되어 있습니다. 아래 [협력사 종합 모니터링 대시보드](#협력사-종합-모니터링-대시보드-partners) 절을 참고하세요.

## 동작 방식

1. 사용자가 웹 페이지에서 `.hwp` 또는 `.hwpx` 파일을 업로드합니다.
2. 서버가 파일을 임시 디렉터리에 저장하고 `soffice --headless --convert-to pdf`를 실행해 PDF로 변환합니다.
3. 변환된 PDF를 바로 다운로드로 응답합니다. 서버에 파일이 남지 않도록 임시 디렉터리는 요청이 끝나면 삭제됩니다.

## 요구 사항

- Python 3.10 이상
- LibreOffice (`soffice` 명령을 사용할 수 있어야 합니다)
- (선택) 한글이 포함된 문서를 올바르게 렌더링하려면 한글 폰트(`fonts-nanum`, `fonts-noto-cjk` 등)가 필요합니다.

## 로컬 실행

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# Ubuntu/Debian 기준 LibreOffice 및 한글 폰트 설치
sudo apt-get install -y libreoffice-writer fonts-nanum fonts-noto-cjk

python app.py
```

브라우저에서 `http://localhost:5000` 에 접속해 파일을 업로드합니다.

## Windows 개인 노트북에서 실행 (집/개인 LAN 전용 서버로 사용)

회사 문서를 제3자 온라인 변환 사이트에 올리지 않고, 개인 노트북을 상시 켜진 변환
서버로 써서 집 LAN 안에서만 접속하고 싶을 때의 절차입니다.

1. **Python 설치**: [python.org](https://www.python.org/downloads/)에서 3.10 이상 버전을
   내려받아 설치합니다. 설치 화면에서 **"Add python.exe to PATH"** 체크박스를 꼭
   선택하세요.
2. **LibreOffice 설치**: [libreoffice.org](https://www.libreoffice.org/download/download/)에서
   Windows용 설치 파일을 내려받아 기본 옵션으로 설치합니다 (Writer가 기본 포함됩니다).
   `converter.py`는 LibreOffice가 PATH에 없어도 기본 설치 경로
   (`C:\Program Files\LibreOffice\program\soffice.exe`)를 자동으로 찾습니다.
3. **소스 코드 받기**: 이 저장소를 내려받습니다 (Git이 있다면
   `git clone https://github.com/dongdong208010049/1st.git`, 없다면 GitHub 저장소
   페이지의 "Code → Download ZIP"으로 받아 압축을 풉니다).
4. **PowerShell에서 실행**:
   ```powershell
   cd 1st
   py -m venv .venv
   .venv\Scripts\activate
   pip install -r requirements.txt
   python app.py
   ```
5. 처음 실행 시 **Windows Defender 방화벽 알림**이 뜨면 **"개인 네트워크"만 체크**하고
   "공용 네트워크"는 체크 해제한 뒤 허용합니다. 이렇게 하면 집 LAN 안에서만 접근
   가능하고, 카페 와이파이 등 공용망에서는 접근할 수 없습니다.
6. 노트북 자신에서는 `http://localhost:5000`으로 접속합니다. 같은 집 LAN에 있는
   다른 기기(휴대폰 등)에서 쓰려면, `cmd`에서 `ipconfig`를 실행해 노트북의 IPv4
   주소(예: `192.168.0.15`)를 확인한 뒤 다른 기기 브라우저에서
   `http://192.168.0.15:5000`으로 접속합니다.

## Windows에서 설치 없이 실행 (포터블)

Python/LibreOffice의 설치 마법사를 실행하지 않고, 압축 풀기 + 더블클릭만으로 실행하고
싶다면 `portable/` 폴더의 스크립트를 사용하세요. 실제로는 "포터블(설치 프로그램 없는)"
버전의 Python과 LibreOffice를 이 폴더 안에 풀어서 쓰는 방식이라, 관리자 권한이나
레지스트리 변경 없이 동작합니다.

1. 이 저장소를 내려받아 압축을 풉니다 (GitHub의 "Code → Download ZIP").
2. `portable\setup.bat`을 더블클릭합니다. Python 임베더블 패키지와 pip를
   `portable\python-embed\`에 자동으로 내려받아 준비하고, 이 프로젝트의 의존성을
   설치합니다. (최초 1회만 인터넷 연결이 필요합니다.)
3. [portableapps.com/apps/office/libreoffice_portable](https://portableapps.com/apps/office/libreoffice_portable)에서
   LibreOffice Portable을 내려받아, 다음 경로에 `soffice.exe`가 있도록 `portable`
   폴더 안에 압축을 풉니다: `portable\LibreOfficePortable\App\libreoffice\program\soffice.exe`
4. `portable\run.bat`을 더블클릭하면 서버가 시작됩니다. 브라우저에서
   `http://localhost:5000`으로 접속합니다.

다른 기기에서도 쓰려면 위 "Windows 개인 노트북에서 실행" 절의 5~6단계(방화벽에서
"개인 네트워크"만 허용, `ipconfig`로 IP 확인)를 그대로 따르면 됩니다.

## 컨테이너로 실행 (Podman)

LibreOffice 설치 없이 바로 실행하고 싶다면 컨테이너 이미지를 사용할 수 있습니다.

> **Docker Desktop 대신 Podman을 권장합니다.** Docker Desktop은 직원 250명 이상 또는
> 연매출 1000만 달러 이상인 회사에서 사용 시 유료 구독이 필요합니다. Podman(및
> Podman Desktop)은 Apache 2.0 오픈소스로 회사 규모와 무관하게 무료이며, 명령어가
> Docker와 거의 동일해 아래 `Dockerfile`을 그대로 사용할 수 있습니다.

```bash
podman build -t hwp2pdf .
podman run --rm -p 5000:5000 hwp2pdf
```

Docker Engine(CLI, Desktop 아님)을 이미 쓰고 있다면 `podman`을 `docker`로 바꿔도 동일하게 동작합니다.

## 협력사 종합 모니터링 대시보드 (`/partners`)

같은 앱에 협력사(제조·구매 공급사)의 **경영 건강도**를 감시하는 대시보드가 함께 들어 있습니다.
담당자가 수치를 입력하는 방식이 아니라, 공공·신뢰 자료를 주기적으로 수집해 정규화·채점하고
협력사 리스트에 신호등으로 표시합니다.

### 화면

| 경로 | 내용 |
| --- | --- |
| `/partners/` | 전사 협력사 리스트. 상단에 **뉴스 티커**(클릭 시 해당 협력사 상세로 점프), 업종별 배치 지도, 종합 신호등·등급, 업종 배지, 카테고리별 신호등, 6개월 추세, 최종 갱신일. 업종별 집계 칩, 검색·업종·자료·신호등·등급·담당자 필터와 정렬(위험 우선 기본) |
| `/partners/<id>` | 협력사 상세. **기업개요(주소·대표자·설립일·주요 생산품 …)**, **최근 3년 매출 그래프**, 위치 지도, **상태 이력(폐업·휴업 이력)**, 개요 변경 이력, 카테고리별 지표 값·점수·스파크라인, 즉시위험 사유, 리스크 이벤트, 제출자료 징구, 지표 직접 입력 |
| `/partners/settings` | **업종 분류 관리·협력사 등록**, 지표 정의(가중치·good/bad 기준·사용 여부) 편집, **지표 추가**, 수집기 상태, 수집 로그 |
| `/partners/map` | 지도 전용 화면. 업종(마커 모양) × 신호등(색)으로 배치를 본다 |
| `/partners/changes` | **변동이력 전용 화면.** 종류(상태·사건·지표·개요)·심각도·협력사·기간으로 좁혀 보고, 줄을 누르면 해당 협력사 상세로 간다 |
| `/partners/api/partners.json` | 리스트와 같은 내용의 JSON (사내 다른 시스템 연동용) |
| `/partners/api/changes.json` | 최근 변경(뉴스 티커 원천). `since`로 마지막으로 본 번호 이후만 받는다 |

- 실 API 연동 코드는 각 기관의 공개 규격에 맞춰 작성되어 있으나, 이 저장소에는 키가 없어 응답 파싱까지 실제 호출로 검증하지는 않았습니다.
  키를 넣고 첫 수집 후 로그의 실패 메시지를 확인해 주세요.

### 뉴스 티커와 변경 강조

수집에서 **값이 실제로 바뀐 것만** `change_log`에 쌓고, 그것을 두 곳에서 보여줍니다.

- **흐르는 띠**: 화면 상단에 고정. 항목을 클릭하면 그 협력사 상세의 해당 위치로 점프합니다
  (`#overview`, `#events`, `#metric-<지표코드>`). 마우스를 올리면 흐름이 멈추고,
  `prefers-reduced-motion`이면 애니메이션 없이 좌우 스크롤로 바뜁니다.
- **변경 강조(한 번만)**: 마지막으로 본 변경 번호를 쿠키(`pm_seen_change`)에 담아, 그 이후에
  바뀐 협력사 행만 왼쪽 노란 액센트 + 한 번의 플래시로 강조합니다. 화면을 본 시점이 기록되므로
  다음 조회에는 강조가 사라집니다(액센트도 함께).

무엇이 '변경'인가:

| 종류 | 기록 조건 |
| --- | --- |
| 상태 | 사업자상태·연금 사업장 상태가 바뀜 (가중치 0 지표) |
| 지표 | 지표의 **신호등이 바뀔 때만** (값의 미세 변동은 무시) |
| 사건 | 새로 확인된 리스크 이벤트 (중복 사건은 제외) |
| 개요 | 대표자·주소 등 개요 값이 바뀜 (이전 값 → 새 값) |

첫 적재는 변경으로 보지 않습니다. 알림봇·타 시스템은 `/partners/api/changes.json?since=<번호>`로
같은 내용을 받아갈 수 있습니다.

### 지도 (업종별 배치)

외부 지도 서비스(타일 서버·지오코딩 API)에 의존하지 않습니다. 사내망에서도 그대로 떠야 하므로
남한 외곽선을 좌표로 들고 있고(`partners/geo.py`), 주소는 행정구역 이름으로 대표 좌표를 찾습니다.

- **마커 모양 = 업종, 색 = 신호등.** 업종을 색으로만 구분하지 않기 때문에 색각 이상에서도 구분됩니다
- 주소는 **국민연금 사업장 자료**(소규모 포함)와 DART 기업개요에서 받습니다
- 같은 지역이 겹치면 나선형으로 흩어 놓고, 번지 단위로 정확히 찍어야 하면 상세 화면의
  개요에서 위도·경도를 직접 입력하면 그 좌표를 씁니다
- '광주광역시 광산구'와 '경기도 광주시'처럼 이름이 겹치는 곳을 섞지 않도록 시·도를 먼저 확정합니다

### 기업개요 (보고 싶은 항목 추가)

개요도 지표처럼 **정의가 데이터**입니다(`profile_fields`). 기본 항목은 주소·대표자·설립일·
주요 생산품·전화·홈페이지·위도·경도이고, `/partners/settings`의 '기업개요 항목'에서 추가합니다.
수집기가 새 코드를 들고 오면 자동 등록됩니다.

개요 값은 **덮어쓰지 않고 쌓입니다**(`profile_values`). 대표자 변경·본점 이전이 확인일과 함께
이력으로 남고, 바뀔 때 티커에도 올라갑니다.

- 모든 현황은 **2023-01부터** 월 단위로 관리합니다(`models.HISTORY_START`).
  수집 기간을 비우고 실행하면 그 전 구간을 다시 맞춥니다.
- **폐업 이력**: 상세의 '상태 이력'에 국세청 사업자상태와 국민연금 사업장 상태의 변화 구간이
  그대로 남습니다(계속사업자 → 휴업 → 폐업, 재개업까지). 폐업이 확인된 시점은 리스크 이벤트와
  티커에도 기록됩니다.
- **최근 3년 그래프**: 연도별 마지막 관측치를 그 해의 값으로 봅니다. 공시 매출이 없으면
  **공공 수주 → 연금 가입자수** 순으로 대체하고, 무엇을 그린 것인지 그래프 아래에 표시합니다.
  막대는 0에서 시작하고(축을 자르지 않음), 과거 연도는 옅게·최근 연도는 진하게 두어
  시선이 최근으로 가게 했습니다. 막대 위에 값, 아래에 전년 대비 증감, 제목 옆에 연평균(CAGR)과
  누적 증감을 함께 보여주고, 막대에 마우스를 올리면 그 해의 값과 전년비가 툴팁으로 열립니다.

색은 데이터 시각화 기준 팔레트를 CSS 토큰으로 고정했습니다(`templates/partners/base.html`).

- 상태색(정상/주의/경고)은 예약색이라 업종 색으로 절대 쓰지 않습니다

### 소규모 협력사를 보는 경로 — 추가로 붙인 것과 남은 후보

국민연금 외에 실제로 쓸 수 있는 경로를 더 찾아 두 개를 붙였습니다.

| 경로 | 무엇이 나오나 | 왜 강한가 |
| --- | --- | --- |
| **공장등록현황** (`factory`) | 공장등록 상태, 용지·건축면적, 등록 종업원수, 생산품목, 대표자, 소재지 | 제조업체가 공장을 등록하면 공장등록대장이 공개된다. **공시가 없는 소기업의 대표자·주소 공백을 메우는** 가장 넓은 경로이고, **등록 취소·말소는 가동 중단 신호**라서 즉시위험으로 처리한다 |
| **조달청 낙찰실적** (`procurement`) | 공공 수주 1년 누계·증감 | 나라장터 낙찰 정보는 공개다. 매출 전체는 아니지만 **사업자번호 단위로 확인되는 실측 매출**이고, 수주가 끊긴 시점이 영업 중단 신호가 된다 |

**교차검증 지표가 둘 생깁니다.** 한 소스만 보면 놓치는 것을 맞대봐서 잡습니다.

- `worker_gap`(연금·공장 인원 괴리): 공장에는 30명으로 등록해 두고 연금은 8명만
  신고하는 식의 불일치 — 인건비 미신고든 가동 축소든 확인이 필요합니다.
- `insured_gap`(연금·건보 가입자 괴리): 정규 인원을 일용·외주로 돌리기 시작하면
  두 수치가 벌어집니다.

이후 남은 경로도 모두 붙였습니다.

| 경로 | 얻는 것 | 어떻게 붙였나 |
| --- | --- | --- |
| **내부 구매·납기** (`internal`) | 납기 준수율, 수입검사 불량률, **선급금·조기결제 요청**, 당사 의존도, 3개월 발주 증감 | ERP 연동(`PARTNERS_ERP_URL`) 또는 CSV(`PARTNERS_INTERNAL_CSV`). 공공자료는 한두 달 늦지만 우리 거래 기록은 실시간이다 |
| **건강보험 사업장** (`health`) | 건보 가입자수, 체납 | 연금과 맞대보는 것 자체가 신호다. 같은 사업장인데 인원이 크게 다르면(일용·외주 전환, 신고 누락) `insured_gap`으로 잡는다 |
| **신용평가사 구독 API** (`credit`) | 등급 | `CREDIT_API_URL` + `CREDIT_API_KEY`. 평가사마다 응답 필드명이 달라 `CREDIT_FIELD_GRADE`/`CREDIT_FIELD_DATE`로 맞춘다. 없으면 CSV 적재 |
| **법인등기·환경·안전** (`risk_list`) | 해산등기, 조업정지, 환경위반, 등기 변동 | 자동 조회 API가 없으므로 열람 후 CSV의 `kind`에 적재한다(`해산`·`조업정지`는 즉시위험) |
| **관세청 수출실적** (`submission`) | 수출 매출 | 본인 발급 자료라 징구 항목(`수출실적증명`)으로 받아 '지표 직접 입력'에 넣는다 |
| **특허·실용신안** (`ipr`) | 보유 건수 | 재무와 상관이 약해 **가중치 0(참고용)**. 대체 불가한 기술 보유처가 흔들릴 때 대응 우선순위를 판단하는 데 쓴다 |

내부 거래 지표는 새 카테고리 **거래**로 리스트에 컬럼이 하나 늘었습니다.
납기·불량·선급금은 점수에 들어가고(가중 15/10/10), 발주 증감은 우리가 줄인 것인지
그쪽이 못 받는 것인지 사람이 판단해야 해서 **참고용(가중치 0)** 으로 둡니다.

CSV 적재 예시는 `data/examples/`에 있습니다.

### 계열사

협력사는 **관계(외부 협력사 / 계열사)** 와 **기업집단** 으로 구분합니다. 계열사도
외부 협력사와 **같은 지표·같은 가중치로** 감시합니다(거래 비중이 커서 빠지면 그림이 안 맞습니다).

- 리스트에 `계열` 배지와 관계 필터, 좌측에 계열사 수와 기업집단별 협력사 수
- 상세에 '같은 기업집단' 카드 — 계열 형제사를 바로 오갈 수 있습니다
- 지정하는 곳: 상세의 '기본정보' 또는 설정의 '협력사 등록'(기업집단은 기존 값 자동완성)

### 픽토그램·신호등·툴팁 (글 줄이기)

리스트 한 칸에 문장을 늘어놓지 않습니다. **신호등(색+모양) + 픽토그램 + 값 한 조각**만
보여주고, 마우스를 올리면(또는 키보드 포커스) 그 칸의 전체 내역이 툴팁으로 열립니다.

- 카테고리별 아이콘: 기업상태(건물) · 재무(동전) · 매출(추세) · 인원(사람) · 경영환경(방패)
- 칸에 보이는 값은 **문제가 있으면 가장 나쁜 지표**, 다 정상이면 그 카테고리의 대표 지표
- 툴팁에는 항목별 값·점수·가중치가 모두 들어가고, 신호는 `● 정상 / ▲ 주의 / ■ 경고`
  기호로도 표시해 색만으로 뜻을 전달하지 않습니다
- 등급·추세·갱신 칸에도 툴팁이 붙습니다(등급 상한 사유, 6개월 점수 흐름, 자료원 목록)

### 규모가 작은 협력사(비외감) 모니터링

금형·지그·검사구 업체는 대부분 외부감사 대상이 아니라 **DART에 재무가 없습니다.**
공시가 없다고 감시를 못 하는 것은 아니며, 이 대시보드는 다섯 경로를 겹쳐 씁니다.
아래는 커버 순서대로입니다.

| 순위 | 경로 | 무엇을 보는가 | 왜 소규모에 통하는가 |
| --- | --- | --- | --- |
| 1 | **국민연금 사업장 자료** | 가입자수, 1인당 신고소득(당월고지금액 ÷ 가입자수 ÷ 9%), 3개월 이탈률, 사업장 탈퇴 | **근로자 1인 이상이면 규모와 무관하게 존재.** 임금 삭감·무급휴직·퇴사 러시가 재무제표보다 몇 달 빠르다 |
| 2 | **법적 사건** | 회생·파산 공고, 부도(당좌거래정지), 공장 경매·공매 개시, 국세 체납 | 공시 의무와 무관하게 공개된다. 소기업 부실에서 가장 확실한 신호 |
| 3 | **국세청 사업자상태** | 계속/휴업/폐업 | 규모 무관, 공급 단절 그 자체 |
| 4 | **신용평가 등급** | 기업신용등급(AAA~D) | 평가사는 비외감 소기업도 등급을 산출한다. 협력사 제출 평가서 또는 평가사 구독 |
| 5 | **정기 제출자료 징구** | 표준재무제표증명, 부가세 과세표준증명, 납세증명서, 4대보험 완납증명 | 국세청 발급본이라 꾸밀 수 없다. **재무를 직접 확인하는 유일한 경로**이고, 제출 지연 자체가 신호다 |

운영 방법:

1. 리스트 상단 **'자료 취약(공시 없음)'** 칩을 누르면 공시 재무가 없는 협력사만 나옵니다. 이 목록이 징구·등급 등록 대상입니다.
2. 협력사 상세의 **'제출자료 징구'**에 제출 기록을 남기면 '자료 제출 경과' 지표가 즉시 재계산됩니다. 제출이 없으면 0점입니다.
3. 제출받은 증명의 수치는 상세의 **'지표 직접 입력'**에 넣습니다. 자료원이 `manual`로 남고, 지표 코드는 DART와 같아서 **공시가 있는 협력사와 동일한 기준으로 채점**됩니다.
4. 신용등급은 `data/credit_grades.csv`(`PARTNERS_CREDIT_CSV`)에 적재합니다. 컬럼은 `biz_no,grade,evaluated_on`이며 `grade`는 AAA~D입니다.
5. 법적 사건은 `data/risk_list.csv`(`PARTNERS_RISK_CSV`)의 `kind`에 `회생 / 파산 / 부도 / 경매 / 공매 / 체납`을 쓰면 즉시위험으로 처리됩니다.

**자료가 없는 것을 '깨끗하다'로 읽지 않게** 등급 상한을 둡니다. 자료 충족률(가중치 기준)이
55% 미만이면 최고 B, 35% 미만이면 최고 C로 제한하고 리스트에 `자료 43% · 상한 B`로 표시합니다.
무료 공개자료(연금·국세·명단)만 붙은 소규모 협력사는 여기에 걸리며, 신용등급을 등록하고
제출자료 수치를 입력하면 상한이 풀립니다. 기준은 `partners/scoring.py`의 `COVERAGE_CAPS`입니다.

소규모에서 먼저 켜지는 즉시위험 신호: **국민연금 사업장 탈퇴**(근로자 0명·폐업 직전),
**회생·파산·부도·경매**, 임금체불 명단 등재, 3개월 인원 30% 급감.

아직 붙이지 않은 확장 후보: 신용평가사 기업정보 API 구독(유료, 비외감 커버가 가장 넓다),
내부 구매·납기 데이터 연동(거래의존도·납기 지연 — 소규모에서는 우리 거래가 가장 빠른 신호),
현장 실사 체크리스트 점수, 대표자 변경·본점 이전 등 법인등기 변동 감시.

### 종합등급 산정

1. 지표별 0~100점 = `good_value`(100점)~`bad_value`(0점) 선형 보간
2. 종합점수 = 값이 있는 지표의 **가중 평균** (자료가 없는 지표는 가중치에서 제외)
3. 자동 감점: 자료 노후(90일 초과) −5, 최근 1년 리스크 이벤트 건당 −3(최대 −15)
4. **즉시위험**에 하나라도 해당하면 점수와 무관하게 E·🔴 — 폐업, 휴업, 국민연금 사업장 탈퇴,
   완전자본잠식, 임금체불 명단 등재, 회생·파산·부도·경매, 3개월 인원 30% 이상 급감
5. 등급: A(85+) · B(70+) · C(55+) · D(40+) · E. 신호등: 🟢70+ / 🟡40+ / 🔴40 미만
6. 자료 충족률이 낮으면 등급 상한(55% 미만 → B, 35% 미만 → C). 위 '규모가 작은 협력사' 절 참고

기준값·가중치는 `/partners/settings`에서 조정하고, 즉시위험 규칙은 `partners/scoring.py`의 `CRITICAL_RULES`에 있습니다.

### 업종(業) 분류

협력사는 **업종 분류**로 구분합니다. 기본값은 금형 · 양산처 · 지그 · 검사구 · 기타이며,
분류도 코드가 아니라 `partner_categories` 테이블의 데이터라서 계속 늘릴 수 있습니다.

- 추가·수정: `/partners/settings` → '업종 분류' (코드·표시명·정렬 순서·사용 여부)
- 코드로 기본값 지정: `partners/seed.py`의 `CATEGORIES`
- 추가하면 리스트 상단 집계 칩(`금형 2 🔴1`), 업종 필터, 협력사명 옆 배지에 바로 반영됩니다
- 협력사에 분류를 지정하는 곳: 상세 화면의 '기본정보' 또는 설정의 '협력사 등록'
- 사용을 끈 분류는 새로 선택할 수 없지만, 이미 지정된 협력사의 배지는 그대로 유지됩니다
- **지표와 가중치는 전사 공통**입니다. 업종별로 다른 지표를 보고 싶어지면 지표 정의에
  적용 분류를 두는 방식으로 확장할 수 있습니다(현재는 미구현).

### 항목 추가

지표는 코드가 아니라 `metric_defs` 테이블의 **정의**로 관리됩니다. 재무·인원·매출·경영환경 외에
항목을 늘릴 때 스키마를 바꿀 필요가 없습니다.

- 화면: `/partners/settings` → '지표 추가' (코드·표시명·카테고리·방향·good/bad·가중치)
- 코드: `partners/seed.py`의 `METRIC_DEFS`에 행 추가
- 추가한 지표는 리스트의 해당 카테고리 컬럼과 상세 화면에 자동으로 나타납니다. 값은 수집기 또는 `models.put_metric_value()`로 채웁니다.

### 실행

```bash
# 샘플 협력사 8곳 + 최근 12개월 목업 데이터로 바로 확인
python -c "from partners import models; from partners.seed import seed_all; seed_all(models.connect('instance/partners.db'))"
flask --app app run   # http://localhost:5000/partners/
```

데이터는 SQLite 한 파일(`instance/partners.db`, `PARTNERS_DB`로 변경 가능)에 저장됩니다.
기존 DB는 앱을 띄울 때 부족한 컬럼이 자동으로 추가되므로(`partners.category_code` 등) 따로 마이그레이션할 필요가 없습니다.
수집은 화면의 '지금 수집' 버튼 또는 `partners.collectors.run_collection()`으로 실행하며,
정기 수집은 cron·작업 스케줄러에서 같은 함수를 호출하면 됩니다.

## 제한 사항

- LibreOffice의 HWP 가져오기 필터를 사용하므로, 복잡한 표/그림/개체가 많은 문서는 원본 한글 프로그램과 서식이 다르게 보일 수 있습니다.
- 업로드 파일 크기는 기본 20MB로 제한되어 있습니다 (`app.py`의 `MAX_CONTENT_LENGTH`에서 조정 가능).
- 변환 시간은 최대 120초로 제한되어 있습니다 (`converter.py`의 `CONVERT_TIMEOUT_SECONDS`).
